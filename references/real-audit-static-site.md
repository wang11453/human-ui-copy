# 真实案例：一个静态站，461 个 SVG，395 个没标

> 2026-10-17，用 `human-ui-copy` 审一个手写静态站（约 20 个 HTML 模板）。
> 真实审计结果，数字可自行复现。

## 背景

站点是手写 HTML + CSS，没有框架、没有构建。图标全部内联 `<svg>`，用 `class="icon"`、`class="ic"` 之类的类名区分用途。

## agent 报回来的结果

```
全站 <svg>       461 个
有标注           66 个
缺 aria-hidden   ≈ 395 个
```

## agent 给的方案

按类名批量补 `aria-hidden="true"`，正则匹配 `class="icon"` / `class="ic"`，排除信息性 SVG。它给出的安全性论证是：

> 有文本的按钮/链接不依赖 SVG 传达信息。

## 为什么这个论证不能直接接受

那句话是一个**假设**，不是验证过的结论。三件事必须先查：

1. **有没有文字为空的按钮/链接？** 图标按钮（关闭、翻页、汉堡菜单）里那张 SVG 是控件唯一的名称。给它加 `aria-hidden` 等于把按钮变成无名按钮，比不修更糟。
2. **有没有 SVG 能获得焦点？** 带 `tabindex`、或被 `<a>` 直接包住的 SVG，加 `aria-hidden` 会产生"焦点落在隐形元素上"。
3. **正则匹配 `class="icon"` 可靠吗？** class 顺序会变、单双引号都有、`<svg>` 标签可能跨行。至少要用 `class="[^"]*\bicon\b[^"]*"`，或者按 DOM 改。

## 正确的顺序

```
① 分类：装饰性（旁边有文字）/ 图标按钮里 / 独立有意义（图表、插图）/ 纯装饰背景
② 只对 ①④ 批量加 aria-hidden="true" focusable="false"
③ ② 修【控件】：加 aria-label，SVG 才 aria-hidden
④ ③ 修【SVG】：role="img" + <title> 或 aria-label
```

## 这件事对 skill 的反馈

- 审计报数字很容易，**报"该改什么"才算审计**。395 这个数字本身不构成结论。
- "agent 说安全"不是安全性。要用可验证的检查（空文字控件、可聚焦元素）来支撑。
- 这条经验已并入 `SKILL.md` 与 `appendix.md` 的无障碍部分。

## 复现

用同一份 skill 跑自己的站：

> 使用 human-ui-copy，模式 = delivery。输出审计报告：`must` 项逐条 是/否 + 证据；`judgement` 项 0–2 分 + 引用片段 + 依据哪个锚点；结尾给建议清单（`must` 优先）。不要自动修改 `judgement` 相关内容。
